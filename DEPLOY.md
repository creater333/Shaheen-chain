# ShaheenChain Backend — Deploy Guide

This folder is the live backend (Flask + SQLite) for the ShaheenChain app
and the admin dashboard. Deploy it once on a public server, then connect
both clients to its URL.

## What connects to it

- **Admin dashboard** (Netlify / Vercel / GitHub Pages): open it → 🔌 Backend
  tab → paste the backend URL + API key → Test Connection → Save & Connect.
- **App v1.6+** (APK, current v1.1): server mode is code-only now —
  the app ships with the backend URL baked in by the developer (no
  Server panel in the app). Users just log in / register; the app
  connects automatically when a URL is baked in.

## Option A — Render (free, easiest)

1. Push this folder to a GitHub repo (or use Render's "deploy from a
   public repo" flow).
2. Render dashboard → New → Web Service → connect the repo. The included
   `render.yaml` fills in the build and start commands automatically.
3. Environment variables (Render → Environment):
   - `SHAHEENCHAIN_ADMIN_KEY` — set a STRONG secret. This is the key the
     dashboard uses. Never leave the default `admin123` in production.
   - `EARNINGS_SECRET` — auto-generated by `render.yaml`.
4. Deploy. Render gives you a URL like
   `https://shaheenchain-backend.onrender.com` — that is your backend URL.
5. First run seeds the demo accounts (admin / admin123,
   demo1 / demo2 / demo3 / demo123). Change the admin password from the
   built-in web panel after first login.

## Option B — Railway

1. `railway init` + `railway up` from this folder, or connect the GitHub
   repo in the Railway dashboard. `railway.json` sets the start command.
2. Variables → add `SHAHEENCHAIN_ADMIN_KEY` (strong secret) and
   `EARNINGS_SECRET` (any long random string).
3. Railway assigns a public domain — that is your backend URL.

## Option C — Oracle Cloud (Always Free)

Follow the Oracle + Cloudflare guide delivered earlier for this project:
a free ARM VM (Always Free is 2 OCPU / 12 GB since June 2026)
running `venv/bin/python app.py` (or gunicorn, same command as the
Procfile) behind Cloudflare. Set the same two environment variables
on the VM.

## Honest limitations

- **SQLite + free tiers:** on Render/Railway free tiers the disk is
  ephemeral — data can reset when the service restarts or redeploys.
  That is fine for testing. For real users, move to a paid disk or a
  Postgres database (a separate migration step).
- **Single worker:** the Procfile uses `--workers 1` on purpose — SQLite
  does not handle multiple writers safely.
- **Security:** token auth is demo-grade, CORS is open on `/api/*`,
  passwords use a salted demo-grade hash (not bcrypt). Restrict CORS to
  your dashboard's exact domain and change all default secrets before
  real users arrive.
- **Local vs server data are separate.** The app's on-device mode and
  server mode never merge; switching modes just switches datasets.
